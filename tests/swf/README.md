# tests/swf/ — standalone end-to-end SWF test files

**Compatibility-audit phase (2026-08-18).** Real, standalone `.swf` files —
one isolated feature per file, increasing in complexity — for end-to-end
file-loading + rendering verification via the desktop CLI
(`flash_runtime --quiet <file>` / `flash_runtime --render <frame> <out.ppm>
<file>`) and, eventually, manual/visual verification on real 3DS hardware
once SD-card SWF loading exists (currently NOT implemented — see
`docs/3ds-limitations.md`).

**Relationship to the existing C++ test suite:** `tests/SwfTestFixtures.cpp`
already builds equivalent (and far more numerous/targeted) SWF byte streams
*in-memory* for the project's 189 `TEST_CASE`s — that suite is the primary,
fast, CI-friendly regression net and already covers the overwhelming
majority of tag-level/opcode-level correctness. This directory exists for
what that suite doesn't cover well: real standalone files you can point the
CLI or a real player/emulator at directly, and — longer-term — files meant
to be loaded from an SD card on real 3DS hardware once that capability
exists. Generated by `tools/swf_test_generator/gen_test_swfs.py` (regenerate
with `python3 tools/swf_test_generator/gen_test_swfs.py` from the repo
root).
